# 华为电脑管家 14 安装辅助工具

基于 [hamflx/huawei-pc-manager-bootstrap](https://github.com/hamflx/huawei-pc-manager-bootstrap) 的社区适配版本，由 [mihahu](https://github.com/mihahu) 整理发布。本项目提供启动器和运行补丁，帮助在非华为 Windows 电脑上安装、运行电脑管家。

**2026-11-27 实测反馈：电脑管家 14.0.7.310 已安装，用户已使用星芒 O1 Pro 成功连接，反馈当前测试正常。** 手机系统此前由用户描述为鸿蒙 7；这是单台电脑与手机的使用反馈，不是所有鸿蒙 7 设备的兼容保证。

## 操作步骤

### 1. 准备工具和官方安装包

1. 下载上面的 **Windows 工具包**，右键选择“全部解压”。源码 ZIP 用于开发，普通安装请选择 Windows 工具包。
2. 确认解压后的 `huawei-pc-manager-bootstrap.exe` 和 `huawei_pc_manager_bootstrap_core.dll` 在同一文件夹。不要直接在 ZIP 内运行，也不要混用其他版本的 EXE 或 DLL。
3. 从[华为电脑管家官网](https://consumer.huawei.com/cn/support/pc-manager/)下载原版安装包。本次验证使用的是 `PCManager_Setup_14.0.7.310(C233)_x64.exe`；官网文件可能更新，下载后核对版本，其他版本需另行验证。
4. 本次实测环境为 Windows 11 x64。先保存正在进行的工作，再退出已有电脑管家、托盘程序和手机协同窗口；如果安装器要求卸载旧版，则按提示卸载并完成重启。

例如，可将工具完整解压到 `D:\HuaweiPCManager`。官方安装包可以保留在“下载”目录，稍后通过“浏览”选择，无需改名或移动到工具目录。

### 2. 通过启动器安装电脑管家

1. 右键 `huawei-pc-manager-bootstrap.exe`，选择“以管理员身份运行”，接受 Windows 权限提示。
2. 点击 **“浏览”**，手动选择刚下载的电脑管家安装包，核对“安装包位置”中的文件名和版本。多个旧安装包并存时，优先手动选择，避免“自动扫描”选中非预期版本。
3. 点击 **“安装”**，在随后打开的华为安装界面完成安装，优先保留默认安装路径。等待安装流程结束，不要同时重复运行其他安装器。
4. 如果要求 **“重启后以管理员启动”**，先完成重启，再重新以管理员身份运行本工具，选择同一个官方安装包重试。弹出重启提示或安装器退出，都不代表已经安装成功。
5. 安装后打开电脑管家“关于”，确认实际版本为本次安装的 `14.0.7.310`。如果仍显示 12，说明还未完成升级；如果启动器报错，先对照下方常见问题处理。

启动器中的两个按钮用途如下：

| 按钮 | 作用 | 使用时机 |
| --- | --- | --- |
| 安装 | 启动所选官方安装器，并在安装过程中部署运行补丁 | 首次安装或从旧版升级 |
| 安装补丁 | 向已安装的电脑管家目录写入本工具内嵌的运行补丁 | 已安装目标版本，需要重新部署补丁时 |

**“安装补丁”不会把电脑管家 12 升级为 14，也不会安装或修复 HMS Core。** 使用前应先退出电脑管家及协同进程，避免文件占用。常规使用无需手工寻找或复制 `version.dll`。

### 3. 处理 HMS Core 与账号登录

1. 安装完成后打开电脑管家。若弹出 **“HMS Core 服务不支持，请连接网络，重新下载并安装最新版本 HMS Core 后再试”**，点击电脑管家提供的 **“下载并安装”**，按官方界面安装或修复 Windows 版 HMS Core。
2. 完成后退出电脑管家托盘程序，再重新打开；若安装器要求重启，先重启电脑。
3. 单独尝试一次华为账号登录。出现“网络异常”时，按下方对应问题排查，记录准确时间和完整提示，不要仅凭电脑管家主界面能打开就认定登录正常。

本次出现过 HMS Core 提示，随后用户反馈已连接成功；最终 HMS Core 版本和具体处理过程未单独记录，因此以上按官方提示补齐服务属于排查步骤，不能保证解决所有登录问题。

### 4. 连接手机并确认结果

1. 解锁手机，打开电脑管家的手机连接入口，按当前界面选择可用的连接方式。
2. 尝试有线连接时使用支持数据传输的 USB 线，并处理手机上的授权提示；尝试无线连接时确认相关 Wi-Fi、蓝牙功能已开启，再按界面引导配对。
3. 如果扫码只跳转网页，或有线连接要求升级电脑管家，先在电脑管家“关于”核对版本，按下面的旧版连接问题处理。
4. 连接成功后，分别验证自己需要的功能，例如投屏、文件传输和重新连接。单项成功不代表所有协同功能都兼容。

**本次实际反馈：星芒 O1 Pro 已成功连接，目前测试没有问题。** 手机完整系统构建号、具体连接方式及每项功能的测试结果尚未单独记录，不将其中任一种连接方式写成已经验证通过。

## 本次常见问题与解决方案

以下结合本次用户反馈、截图和程序行为整理。注明“排查建议”的内容尚无单独的修复闭环记录。

### 1. 电脑管家 12 扫码跳转网页，有线提示升级

**本次现象：** 使用旧版电脑管家时，用户反馈扫码跳转网页、有线连接要求升级；改用本次电脑管家 14 适配版后，反馈星芒 O1 Pro 已连接成功。

**处理：** 使用本仓库发布的 Windows 工具包配合官方 `14.0.7.310(C233)` 安装包，按照上面的流程升级，随后在电脑管家“关于”确认实际版本再配对。仅替换启动器或点击“安装补丁”无法完成电脑管家升级。

如果已经是 14，仍出现相同提示，保留手机完整系统版本、电脑管家版本、连接方式和截图继续定位；本次反馈不足以证明扫码跳网页只有版本过旧一种原因。

### 2. 安装弹窗要求重启后以管理员启动

**处理：** 保存工作，按照安装器要求重启。重启后以管理员身份运行本工具，重新选择官方安装包，再点击“安装”。如果提示先卸载旧版本，先通过 Windows“设置 → 应用”完成卸载，并处理卸载器要求的重启。

若反复出现，不要连续点击安装；记录弹窗内容和最新安装日志，检查旧版是否仍在、重启是否完成，以及本次选择的安装包是否正确。

### 3. `Installer exited successfully, but PCManager.exe was not found`

**本次截图中的报错：** 安装器返回了退出码 `0`，但启动器没有找到预期的 `PCManager.exe`。

**含义：** 退出码 `0` 只说明该安装器进程正常退出，不能证明电脑管家已经装好。重启提示、取消安装或安装到其他目录等情况需要分别核实，不能仅靠此报错确定原因。

**处理：** 先完成安装器要求的卸载或重启，再按操作步骤重试。检查默认安装目录 `%ProgramFiles%\Huawei\PCManager` 中是否存在 `PCManager.exe`，并确认电脑管家的实际版本。当前工具按默认路径检测安装和部署补丁；如果使用了自定义安装目录，应改用默认目录重新安装，或先提交日志进一步定位。

### 4. “HMS Core 服务不支持”

**本次出现过该提示。处理建议：** 使用电脑管家弹窗提供的“下载并安装”入口补齐或修复 Windows 版 HMS Core，然后退出托盘程序并重新打开，按安装器要求重启。手机上的 HMS Core 无法替代 Windows 端服务。

如果反复提示，记录 Windows 端 HMS Core 的实际版本和安装结果，并查看其日志。本工具部署的电脑管家运行补丁不等于 HMS Core 安装包；最终使用的 HMS Core 版本和修复过程本次未单独记录。

### 5. 安装成功，但登录华为账号显示“网络异常”

**本次早期出现过该现象；尚未单独记录账号登录的最终复测结果和确定根因。** 后续手机连接成功也不能替代账号登录验证。

**排查建议：**

1. 核对 Windows 日期、时间和时区，确认电脑联网，并尝试在浏览器中打开华为官网。
2. 如有 HMS Core 提示，先完成上一项的服务安装或修复，再退出电脑管家托盘程序并重新打开登录。
3. 若正在使用 VPN 或代理，可临时暂停后重试，测试结束恢复原设置；也可换用手机热点对照。记录不同网络下是否出现相同提示，这只是定位网络相关因素，不是确定修复。
4. 仍然失败时记录报错时间、完整提示、电脑管家和 HMS Core 版本，结合下面的日志继续定位。

### 6. 写入补丁失败、文件正在使用或拒绝访问

**排查建议：** 先正常退出电脑管家、托盘程序和协同窗口，再以管理员身份打开启动器。已安装目标版本时，可点击“安装补丁”重试。

确认没有正在进行的安装或传输任务后，如相关进程仍未退出，可使用本工具的“终止所有进程”，再重试补丁部署。持续失败时查看日志中具体的文件路径和错误；文件锁或权限错误不能当作安装成功。

### 7. 日志出现 `ArchMismatch` 或 `Bincode Error`

**本次已知限制：** 安装注入核心是 x86，无法直接注入部分 x64 辅助进程，详细日志可能出现 `ArchMismatch("Expect x64", "Got x86")`。依赖库外层也可能把该错误显示为 `Bincode Error`，应查看完整错误链。

**处理：** 同时核对安装器最终结果、电脑管家实际版本和连接情况。本机后续安装及连接成功，说明单条此类日志不足以认定整个安装失败；若安装中断或功能异常，应保留对应日志继续定位，不要混入来源不同的 DLL 尝试修复。

### 8. 工具窗口显示 `0.1.9-883d64a`，是不是下载了电脑管家旧版

这是 **安装辅助工具的版本号**，不是电脑管家的版本号。本次发布保留已实测的该版本二进制；电脑管家版本应在其自身“关于”页面确认。发布标识、代码提交及文件校验信息见附件 `BUILD-INFO.json`。

### 9. 电脑管家更新后，原来可用的功能异常

**排查建议，尚未验证后续新版：** 先记录更新后的版本，退出相关进程，再用同一工具包尝试“安装补丁”，检查日志和功能是否恢复。该按钮只重新部署现有补丁，不代表工具已经适配新版本；仍失败时保留日志提交反馈，本次验证范围以 `14.0.7.310(C233)` 为准。

## 日志与问题反馈

启动器内点击 **“打开日志”** 或 **“打开日志文件夹”** 查看本次运行记录。也可将以下路径粘贴到资源管理器地址栏；相关组件尚未安装或未产生日志时，目录可能不存在。

| 组件 | 日志目录 |
| --- | --- |
| 本工具 | `%LOCALAPPDATA%\hamflx\huawei_pc_manager_bootstrap\cache` |
| 电脑管家 | `C:\ProgramData\Comms\PCManager\log` |
| Windows 版 HMS Core | `C:\ProgramData\Huawei\HMSCORE\log` |

进一步排查或反馈问题时，请提供 Windows 版本、电脑管家完整版本、手机型号和完整系统构建号、连接方式、出错时间、完整提示，以及相同时间段的相关日志。对外提供前移除账号、令牌、二维码、序列号等个人信息。

补丁原理、构建验证和恢复说明见[适配说明](docs/pcmanager14-adaptation.md)。

## 本版修改与验证

本版基于 `wornik` 的 `v0.1.13-fix`，保留其 DLL 固定修复，补充初始化失败处理、注入诊断、固件缓冲区边界处理和有边界检查的 SMBIOS 改写。原 UUID、原始句柄及其他固件记录保留，固件返回值只影响加载补丁的进程，不写入实际 BIOS。

公共模块在 x64/x86 各通过 10 项测试，启动器通过 35 项测试，共 55 次测试执行、45 项不同测试。真实 DLL 加载、系统版本接口转发、固件查询、子进程注入及模块释放后的回调验证均通过。

发布二进制沿用用户已测试的 `0.1.9-883d64a`，代码基线为 `883d64aa1fd02c229521abc254bfcf3a506077ee`。`pcmanager14-test1` 是本分支发布标识；上游 Cargo 包版本仍为 `0.1.9`。源码标签还包含后续发布说明和 CI 触发配置。

x86 安装核心对部分 x64 辅助进程会记录 `ArchMismatch`，本机后续安装和连接成功，但其他硬件、HMS Core 版本、完整系统构建号及各连接方式仍需分别测试。本项目为社区工具，不代表华为官方支持。

## 从源码构建

需要 Windows x64、Visual Studio 2022 C++ 构建工具、Windows SDK 和 Rustup。

```powershell
git clone --branch pcmanager14-adaptation https://github.com/mihahu/huawei-pc-manager-bootstrap.git
cd huawei-pc-manager-bootstrap
rustup toolchain install nightly-2025-02-01-x86_64-pc-windows-msvc --profile minimal
rustup toolchain install nightly-2025-02-01-i686-pc-windows-msvc --profile minimal --force-non-host
.\build-release.bat
```

输出位于 `dist`。启动器与核心为 x86；先行构建的 x64 `version.dll` 嵌入启动器。
测试与探针命令见[适配说明](docs/pcmanager14-adaptation.md#自动验证)。

GitHub Actions 对 `master` 与 `pcmanager14-adaptation` 的推送、PR 执行构建验证。此次 `pcmanager14-test1` 发布使用已实测二进制，未使用上游 `v*` 标签自动发布流程。
